# Agent Note: 工作区项目循环面板

Status: implemented

[English](2026-09-03-workspace-project-cycle-panel.md) | 中文

## 问题

Web Client 提供会话与工作区，但没有项目级清单把产品需求贯穿功能规划、原型、开发、测试、修复和部署。用户可以手动发送每条指令，但应用无法保存选定功能集、把后续轮次关联到原型版本，也无法无人值守地连续执行测试与修复迭代。

## 决策

可选 Bundle `@deepseek-ai/dsh-client-ui-xgg-cycle` 向 `conversation.session.header.utilities` 和 `sidebar.footer.action` 同时贡献一个本地化流程面板。空白会话隐藏 conversation chrome 时，侧边栏注册仍让入口可达。随附 Web bundle 包含同一个插件行，而包自有 patch 让其他兼容 Web Profile 可以独立安装它。

一个按工作区分键的浏览器持久化 store 拥有项目事实、需求、已确认功能分组、原型与轮次记录、手动问题、部署设置和自动循环状态。根作用域控制器拥有该 store 与所有完成监听。因此会话导航可以卸载 header 占位者，而不会取消它发起的工作。

需求扩展使用专用规划会话。需要连续上下文时，原型、开发、测试、修复与部署轮次会复用最新的存活项目会话；没有可用目标时则创建新的工作区会话。每个等待回复的投递会先打开目标，因为关闭的 Client Session 窗口不会保留完成判断所需的实时事件。

每个阶段消息都要求在阶段工作前完成仓库梳理。Agent 会读取适用的仓库指令、项目文档与清单、相关源码与测试以及 Git 状态，然后报告当前技术栈、入口、已实现行为、约束和剩余缺口。已有实现优先于面向新项目的默认选型，用户未提交改动会得到保留。需求规划只有只读权限；交付轮次只能在梳理明确增量范围后执行。复用的会话可以核对仓库没有变化，而不必重复完整梳理。

会话等待器只在观测到新 assistant 消息，或从运行转为空闲，且待处理队列为空后结算。它从会话事件窗口读取 assistant 文本。协议读取器扫描每个可解析 JSON 载荷，并选择带预期键的对象，因此同一回复中的源码或配置示例不会遮挡流程结果。

无人值守路径会生成功能点、创建带版本的原型、启动正式开发，并交替执行测试与修复轮次。不存在可操作的 P0/P1 问题时成功停止；完成五轮修复后以有界结果停止。浏览器重载会把失去控制器的忙碌状态改成明确的停止状态，而不会暗示内存控制器仍在运行。

直连服务器密码不会进入浏览器持久化，并在面板投递记录中打码。部署消息仍包含密码并成为持久会话历史；面板会在投递前说明这一后果。

## 考虑过的替代方案

**把循环保留在 `PopupPanel` 中。** 拒绝，因为打开投递目标会改变所选会话，并可能卸载会话 header 占位者。组件拥有的状态和等待会在第一次自行投递时消失。

**需求扩展与项目实现共用一个会话。** 拒绝，因为长时间实现轮次进行时提交的扩展会排在其后，而完成监听可能把错误轮次关联到流程记录。规划与实现具有不同的连续性需求。

**依赖手工录入的基础信息作为项目描述。** 拒绝，因为自由格式字段无法可靠描述已有模块、仓库指令、本地改动、测试或面板外已完成的工作。Agent 会先从工作区读取这些事实，再解释本次增量需求。

**把第一个可解析 JSON 块当作结果。** 拒绝，因为实现回复常包含有效的 `package.json`、配置或其他 JSON 块。每个解析器必须识别自己的带键对象。

**把部署密码与项目其他内容一起持久化。** 拒绝，因为便利性不足以支持在浏览器存储中保留可复用密钥。部署必须把凭据传给所选 agent，因此仍需明确说明会话历史暴露。

## 后果

Web Client 无需新增 Host 服务或修改 agent loop 即可获得连续的项目流程。已有仓库会被当作当前项目，而不是空白脚手架；代价是每个已投递阶段会增加仓库读取、梳理文本与摘要 token。其他代价包括较大的浏览器 bundle、无法跨设备同步的工作区本地状态、投递时的主动会话导航，以及对结构化阶段回复的严格依赖。停止控制器可以阻止后续轮次，但无法回滚 agent 已修改的文件或部署。

本包虽然在浏览器实现，但仍拥有面向模型的用户消息。README 记录其 token 与 KV-cache 影响，locale 字典则把呈现文案与中文流程提示分开管理。
